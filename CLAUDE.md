# Utah Athletic website

Marketing site for Utah Athletic Soccer Club (utathletic.com). Astro, static output, deployed on Vercel.

## How this repo works

- **Studio** opens on **Start here** (`studio/tools/StartHere.tsx`): buttons for common jobs. **Sidebar** (`studio/structure.ts`) mirrors the website: Website pages (Home page; each program opens to its page content plus its tryout sessions or sessions, Futures also its registrations; the adult leagues; Tryouts page; Tournaments & Events with its page content; Network page; Contact page; Futures also has its registration page and waiver), Site-wide components (Development model, plus any future content shared across pages), People and places (Staff, Venues), Inbox (Form messages, Futures registrations, Sent emails) and Settings (Site settings, Waivers, Automatic emails, Region settings). New tryouts from Academy's or Club's list start with that program (`TRYOUT_TEMPLATES`). Vision and Releases are shown to administrators only (`ADMIN_TOOLS` in `studio/sanity.config.ts`).
- **Content lives in Sanity** (project `03wnsd9x`, dataset `production`). Staff edit it in the Studio at https://utah-athletic.sanity.studio; the Studio source and schemas are in `studio/` (see `studio/README.md`).
  - Document types: `staff` (one per person: name, title, optional description, email and a Studio-only phone, headshot), `program` (4 fixed docs, ids `program.<key>`; `leadership` and each region entry's `leaders` and `coaches` are lists of `{ person: ref → staff, title? }`, the title overriding the person's for that spot; Rec has no coaches list, see `NO_COACH_LIST` in `src/data/site.ts`, and a region tab skips Coaching staff until a coach is added; each region entry also has optional `ages` and `fees` (rows of age group, price, note) that set its price; Club instead has `ageTabs` (age range, a price per region, note, included and not-included lists; `AGE_TAB_PROGRAMS` in `studio/schemaTypes/program.ts`), shown as tabs in each region's Fees section (`FeeTabs` in `RegionTab.jsx`); the program's overview price is the lowest across running regions), `region` (3 fixed, `region.<key>`, "Region settings" in the sidebar; label, area), `venue`, `tryoutSession`, `recSession` and `futuresSession` (one region, venue, price and set of dates each; Futures adds a `classes` list; `status` is `auto` unless the editor overrides it, worked out on the visitor's date by `sessionStatus` in `src/lib/schedule.ts`; Rec and Futures prices on program and region pages come from these), `adultLeague` (2 fixed, `adultLeague.upsl` and `adultLeague.rec`, "Adult: UPSL" and "Adult: Adult Recreation" in the sidebar: each league's page copy, season, week, cost, staff, home fields and questions; see `ADULT` in `src/data/site.ts`), `event`, the `siteSettings` singleton (main email, Tryouts button label, social links, default share image, logo and favicon, marketing tracking IDs), the `componentDevelopment` singleton ("Site-wide components" in the sidebar, `studio/schemaTypes/components.ts`: shared development model defaults, heading, intro and each pillar's label, detail and focus areas; merged over Site settings like the page singletons), the page singletons in `studio/schemaTypes/pages.ts` (`pageHome`: home page sections, collage, videos, Professional tier, Adult pathways heading; `pageTryouts`; `pageEvents`: intro, cards, highlight reel; `pageContact`; `pageFutures`: registration and thank-you wording; each with its Search and sharing; `fetchContent` lays their fields over Site settings, same field names, so `content.ts` reads one settings object) and the `networkPage` singleton (all of /network/ except the map's club locations). Editors can't create or delete the fixed documents (programs, regions, Site settings, Network page).
  - `src/lib/sanity.ts` fetches published content at build time (with `SANITY_READ_TOKEN`, a Viewer token, set in `.env` and in Vercel; Sanity hides ids with a dot like `program.academy` from anonymous reads) and validates it with Zod; a bad document fails the build with its id and field. `src/lib/content.ts` reshapes it into the one `data` object pages and islands share (image URLs from Sanity's CDN, times and ages formatted, development model merged per program: each program's devPillars (summary, photo, optional overrides) over the shared defaults).
  - Publishing in the Studio triggers a Vercel rebuild through a webhook. Drafts never reach the site.
  - When a schema changes, update `studio/schemaTypes/`, the Zod schema in `src/lib/sanity.ts` and the mapping in `src/lib/content.ts` together, then `cd studio && npm run deploy`.
- **Page layout** (order and hide): every page except Contact and the Futures registration pages has a "Page layout" list in the Studio (`pageLayout` in helpers.ts, `studio/components/SectionLayoutInput.tsx`): ↑ ↓ to reorder and a Show switch per section. The order is saved as section keys (programs: `sectionOrder` and `regionSectionOrder`; adult leagues and the Network page: `sectionOrder`; page docs: `homeSectionOrder`, `tryoutsSectionOrder`, `eventsSectionOrder`); the switches write the existing hide fields (programs `hide`/`hideRegion`, others `hide`, page docs `homeHide` …, now hidden fields; Contact keeps its Hide sections checkbox). Sections and keys are in `studio/shared/sections.ts`; `orderOf(kind, saved)` gives the order (saved first, any new section after its default neighbour) and `FIXED_SECTIONS` stay put (program `explore`). Pages draw sections from a key map in that order and number only those shown; heroes, the Tryouts filters and Explore the pathway are fixed. Futures region tabs default to sign-up first. The development model is its own section (`dev`), shown when both Site-wide components and the program's layout allow it.
- **Content that stays in code:** nav, pyramid geometry, collage tile layout, compare row labels and columns, pathway, network map nodes (`NETWORK_NODES`) and the fixed section headings on program pages ("Where we play", "Season overview") are in `src/data/site.ts` and the components. Arrows on buttons and links are added in code, so Studio fields hold the words only. Optional "Placeholder note" fields show the dashed placeholder tag until an editor clears them. The page intros on /tryouts, /events and /contact, the events page cards, contact form topics and Futures registration page copy are in Site settings; Rec "How we play" and each program's map pins are on its program document (a pin is placed at a town from `studio/schemaTypes/towns.ts`, shared with the site). Program and region ids are structural and live in code too.
- **Routes:** `/` home, `/<program>/` program overview, `/<program>/<region>/` region tab (all 12 exist; "soon" and "not offered" regions get their own state, never a 404), `/adult/upsl/` and `/adult/recreation/` (adult leagues, `AdultPage.jsx`; linked from the boxes under the home pyramid), `/tryouts/` (`?region=&level=`), `/events/`, `/network/`, `/contact/` (`?region=&program=`). Old `/programs/<key>/` URLs redirect (see `astro.config.mjs`).
- **Home and program pages are one React island**, `src/components/app/UAApp.jsx`: routing, transitions and region memory. It renders `Home.jsx` (collage, pyramid, tryouts near you, tournaments, network teaser, docuseries) and `ProgramPage.jsx` (hero, region tabs, overview sections), which uses `DevModel.jsx`, `CompareTable.jsx` and `RegionTab.jsx`. Opening a program pushes its URL; back/forward and Escape work. The pyramid's Professional tier zooms into `/network/`.
- **Other pages** are Astro pages with small islands: `TryoutsApp.jsx`, `EventsApp.jsx`, `ContactApp.jsx`, `NetworkMap.jsx` (d3, `src/data/world-geo.json`). `SiteHeader.jsx` and `SiteFooter.jsx` are shared by every page.
- **Region memory:** the `ua_region` cookie (1 year) plus `?region=`. Picking a region anywhere sets it; Club and Rec open on it, and so do `/tryouts/` and the header's Tryouts button. Helpers are in `src/lib/schedule.ts` (also date formatting, event status and "next tryout").
- **Dates:** tryouts in the past drop off and event status updates on the visitor's own date after load, so a stale build never shows old dates as open.
- **Places and directions:** venues, tournaments (`event.place`) and map pins (`mapHub.place`, instead of a listed town) can hold a `place` (name, address, geopoint, Google place id) picked with the Studio's place search (`studio/schemaTypes/place.tsx`, `studio/components/PlaceSearch.tsx`): Google Places when `SANITY_STUDIO_GOOGLE_MAPS_KEY` is set in `studio/.env` (see `studio/.env.example`), else OpenStreetMap (Photon). Picking a venue's place also fills its address (and empty name). Every venue and tournament location on the site is a directions link from `directions()` in `studio/shared/places.ts` (Google Maps directions, to the exact spot when known, else a search for name and address); on Apple devices a click handler in `Base.astro` opens Apple Maps instead.
- **Locations map** (`src/components/UtahMap.jsx`, in each program's "08 · Regions" section): pins from each program's Map pins (Studio), towns in `studio/schemaTypes/towns.ts` (re-exported as `CITIES` from `src/data/locations.ts`, with the service counties); geometry in `src/data/utah-geo.json`. Regenerate both geometry files with `npm run geo:build`. Both maps are lazy-loaded.
- **Images:** content photos are uploaded in the Studio and served from Sanity's CDN at fixed widths (`W` in `src/lib/content.ts`). `content.ts` turns each one into `{ src, pos?, alt? }`: `src` keeps the editor's crop, `pos` is a CSS position from the editor's hotspot (re-expressed relative to the crop) and `alt` is the editor's description. Components use `pos` as `object-position` (`background-position` for the home collage) and `alt` as the alt text, falling back to their own position and alt when the editor hasn't set one, so new image spots should do the same. Staff headshots render through `Headshot` in `ui.jsx`, a dashed placeholder until one is uploaded. The page heroes on /tryouts, /events and /network still use local files in `src/assets/images/` through `src/lib/assets.ts` (key, or `<key>@lg` for the large size).
- **Styles:** design tokens are in `src/styles/global.css`, along with the named hover classes (`.hv-*`), the form field class (`.ua-input`) and the phone-width rules. Components style themselves inline, matching the prototype markup. Shared pieces (kickers, buttons, form fields) are in `src/components/ui.jsx`. Use the CSS variables; don't hardcode new colors. Icons are Phosphor (`@phosphor-icons/react`).
- **Transition modes:** `expand` is the default. `zoom` and `curtain` also exist; pass `transition="zoom"` to `UAApp`, or `showModes` to show the picker dock while testing.
- `docs/` is internal and never published. `docs/rec-program-plan.md` holds rec program decisions.
- **Design updates:** follow `docs/DESIGN-SYNC.md`. Content changes from a handoff are made in the Studio, not in code. Run `npm run design:extract -- <handoff.zip, handoff folder or export.html>`, diff `docs/design-reference`, and port only what changed using the map in that doc.

## Search and sharing

- The live domain is `site` in `astro.config.mjs` (`SITE_URL`, default `https://utathletic.com`); canonical links, link previews, `/sitemap.xml` (`src/pages/sitemap.xml.ts`, built from the programs, regions and adult leagues; "not offered" regions left out) and structured data use it. `/robots.txt` points to the sitemap and keeps `/api/` out.
- Every page passes `title`, `description` and `image` to `Base.astro`, which writes Open Graph and Twitter tags, the icons (`public/favicon-32.png`, `icon-192.png`, `apple-touch-icon.png`) and schema.org JSON-LD: the club as a SportsOrganization on every page, plus WebSite (home), SportsEvent per tournament (/events) and FAQPage (adult leagues). `noindex` keeps a page out of search (payment thank-you, 404).
- Titles and descriptions default to search-friendly wording in `src/lib/content.ts` (`seoOf`), e.g. "Academy: Elite Youth Soccer in Utah"; region pages name the town. Editors can override any of them, and the share image, in each document's "Search and sharing" section (programs, adult leagues, Network page, and Site settings for home, Tryouts, Events and Contact; Site settings also has the default share image). Share images are 1200 x 630 JPEG crops around the hotspot (`shareImageUrl` in `src/lib/sanity.ts`).

## Marketing tracking

- Site settings > Marketing holds the Google Analytics 4, Meta Pixel, Google Ads (plus a conversion label per action) and Google Tag Manager IDs. `content.ts` keeps an ID only if it matches its exact format (it goes into a script); `Base.astro` loads each tool only when its ID is set and defines `window.uaTrack(kind, { value, id })`, which reports to every tool that's on. Kinds: `purchase` (Futures thank-you page, once per Stripe session via `?cs=&value=` on the success URL), `lead_trial` (trial, invite), `lead_interest` (interest, register), `contact` (contact, adult) from `useSubmit` in `ui.jsx`, and `ollie` (any click to an outside registration link's host). No names or emails are ever sent.
- Logo and favicon: Site settings > Logo and icon. The header, structured data and emails use the logo (`brandEmails()` swaps it into emails as a PNG); the favicon is cut into 32, 192 and 180 px squares. Empty keeps `public/logo-ua.avif` and the icon files in `public/`.

## Forms and payments

- Pages are static; only `src/pages/api/*` runs on the server (Vercel adapter, `prerender = false`). Server-only helpers and the env vars they read are in `src/lib/server/index.ts`; never import it from a page or island. API URLs end in a slash (`trailingSlash: 'always'`).
- Every form uses `useSubmit` and `FormGuard` from `ui.jsx` (honeypot field plus Cloudflare Turnstile when its keys are set). `/api/submit/` saves a `submission` (contact, trial, invite, interest, register, adult) and emails the leaders the page shows (`recipients()`: the program's region leaders, else the region's, else the main email; the /contact form always goes to the main email), then sends the person a confirmation naming who will get back to them within 48 hours. Every email (auto-replies, staff notices, Futures confirmation) is built in `src/lib/server/email.ts` from one table-based layout in the site's colors; the logo is a PNG on Sanity's CDN so it works on any domain. Auto-replies go to whatever address is typed, so keep the honeypot and switch on Turnstile in production.
- **Automatic emails** (Studio > Settings > Automatic emails): one fixed `emailTemplate.<key>` document per family-facing email (form auto-replies `trial`, `invite`, `register`, `interest`, `adult`, `contact`, and `futuresPaid`), with subject, preview, kicker, heading, headingAccent, message, signoff and footer. `message` uses the group email editor as a field (`studio/components/RichTextInput.tsx`, saving JSON blocks; older plain text still reads, via `readBlocks`), and names are filled run by run (`fillTemplate` with `keepEdges`). Keys, titles, the {Field} names each can use and the default wording are in `studio/shared/emailTemplates.ts`; `brandEmails()` loads the published wording before sending and `email.ts` fills it with `fillTemplate` (an empty field uses the default; an empty value drops with its commas). The cards and details blocks and the staff notices stay in code.
- **Waivers** (`waiver` documents, Studio > Settings > Waivers): title, text, optional checkbox wording and `requiredFor`, a list of registration forms from `studio/shared/registrationForms.ts` (only `futures` today). A form shows every waiver required for it, each with its own required checkbox; `/api/futures/checkout/` re-reads the required waivers and rejects the registration unless every one is ticked, then saves a copy of each (`waivers` on the registration: title, text, acceptedAt, weak link). Registrations from before keep `waiverText`/`waiverAcceptedAt`. A new registration form adds its value to `REGISTRATION_FORMS` and does the same check.
- Futures registers and pays on the site: `/futures/register/?session=<id>` (`FuturesRegister.jsx`) posts to `/api/futures/checkout/`, which checks the session is open and has spots, saves a pending `futuresRegistration` and returns a Stripe Checkout link priced from Sanity. `/api/stripe/webhook/` marks it paid (emails family and leaders, sets the session Full when `capacity` is reached), expired, failed or refunded. Recreation still uses Ollie.
- **Pricing page** (Studio > Pricing, `studio/tools/Pricing.tsx`): every price in one place: each program's age tabs by region (Club), other programs' region fees (Rec), Rec and Futures session prices and the adult leagues. Edits are held until Publish prices, which saves them in one transaction (one rebuild) and also patches any open draft so publishing it later doesn't undo the price. It can also add or remove Club age groups (new ones copy another group's included lists) and add Rec and Futures sessions, blank or copied from another session, with Futures classes built in the form (weekly from a day, times and date range, then edited, removed or added one by one; first and last class come from the list) (`tools/pricingDialogs.tsx`); clicking a row opens the same forms to edit an age group (ages, prices, note, lists), a region fee or a session (every field, status, classes). These save and publish straight away. Notes and inclusions stay on the program.
- **Tryouts** (`tryoutSession`): a named tryout (e.g. "2027 Academy Tryouts") per program and region with one Ollie link and `groups`, each age group (ages, players, optional own link) with its `days` (date, venue, start, end). Older one-group documents (ages and days at the top) still read as one group; `.sanity-import/merge-tryouts.mjs` merges them. `tryoutsFor` (schedule.ts) keeps groups with days left on the visitor's date and adds `next`, `when` (date range), `ages` and `players`: the home card, region pages and program status show the tryout's name and summary (the home "Play for us" section shows only programs with something to register for in the visitor's region, and the trial request form when that region has no tryouts); /tryouts shows each tryout, then each age group with its days and Register.
- **Tryouts page** (Studio > Tryouts, `studio/tools/Tryouts.tsx`): every tryout by program (Academy, Club) and region, with filters and past tryouts; add (program and region filled in), copy, edit (patches any open draft too) and delete, with age groups (Copy group) and their days, and a New venue form using the place search. Form pieces shared with Pricing are in `studio/tools/formParts.tsx`.
- **Registrations page** (Studio > Registrations, `studio/tools/Registrations.tsx`): players by US Soccer age group (Aug 1 to Jul 31 seasonal year, U3 to U18) and gender, with copy emails, CSV and group email. Age group, season and season end year are saved on each Futures registration at checkout; the rules, the audience filter and where each program's registrations come from (`SOURCES`) are in `studio/shared/registrants.ts`, shared with the site. The message is written in `studio/components/RichTextEditor.tsx` (bold, italic, links, lists; pasted text is plain) and saved as `bodyRich`, JSON blocks from `studio/shared/richText.ts` (`body` keeps a plain-text copy); the site re-checks it with `parseRich` and builds the HTML itself in `email.ts` (`richHtml`), escaping all text and allowing only http(s), mailto and tel links, so no editor HTML is ever sent. Name fields (`NAME_FIELDS`: {Parent first name}, {Parent full name}, {Player first name}, {Player full name}) are plain text in the message and subject, filled per family by `fillText`/`fillFields` in `/api/broadcast/` (siblings joined with "and"; `recipientsOf` keeps `playerFirsts`). The editor sets its own bold weight (`.ua-rte b`) because the Studio's lighter bold makes the browser think text isn't bold. Sending saves an `emailBroadcast` (Studio > Inbox > Sent emails) and calls `/api/broadcast/`, which re-derives the recipients from the saved filter, sends one email per family through Resend's batch API and logs the result; each one sends once. `src/middleware.ts` replaces Astro's `checkOrigin` so the Studio's address (`STUDIO_ORIGINS`) may call that one route. The Studio calls the site at `SANITY_STUDIO_SITE_URL` (default the vercel.app address; change at launch).
- `submission`, `futuresRegistration` and `emailBroadcast` ids contain a dot (hidden from anonymous reads), use `liveEdit` (no drafts) and can't be created in the Studio; registrations can't be deleted. Emails are skipped quietly without `RESEND_API_KEY`; the Studio is the record. Email sends from `mail.utathletic.com` (Resend, DNS at GoDaddy); the club's Google Workspace mail is on `utathletic.com`.

## Deploying

- Push to `main` deploys to production automatically on Vercel.
- Any other branch gets a preview URL. Use a branch for anything that needs review before going live.
- Always run `npm run build` before pushing; fix errors first.

## Writing rules

- No em dashes in any copy. Use periods, commas or colons instead.
- Keep copy short and parent-friendly. Ages are written U5, U9 to U12, etc.
