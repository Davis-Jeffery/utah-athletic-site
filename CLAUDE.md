# Utah Athletic website

Marketing site for Utah Athletic Soccer Club (utathletic-club.com). Astro, static output, deployed on Vercel.

## How this repo works

- **Content lives in Sanity** (project `03wnsd9x`, dataset `production`). Staff edit it in the Studio at https://utah-athletic.sanity.studio; the Studio source and schemas are in `studio/` (see `studio/README.md`).
  - Document types: `staff` (one per person: name, title, optional description and email, headshot), `program` (4 fixed docs, ids `program.<key>`; `leadership` and each region entry's `leaders` and `coaches` are lists of `{ person: ref → staff, title? }`, the title overriding the person's for that spot; Rec has no coaches list, see `NO_COACH_LIST` in `src/data/site.ts`; each region entry also has optional `ages` and `fees` (rows of age group, price, note) that set its price, and the program's overview price is the lowest across running regions), `region` (3 fixed, `region.<key>`, "Region settings" in the sidebar; label, area), `venue`, `tryoutSession`, `recSession` and `futuresSession` (one region, venue, price and set of dates each; Futures adds a `classes` list; `status` is `auto` unless the editor overrides it, worked out on the visitor's date by `sessionStatus` in `src/lib/schedule.ts`; Rec and Futures prices on program and region pages come from these), `adultLeague` (2 fixed, `adultLeague.upsl` and `adultLeague.rec`, "Adult leagues" in the sidebar: each league's page copy, season, week, cost, staff, home fields and questions; see `ADULT` in `src/data/site.ts`), `event`, the `siteSettings` singleton (main email, Tryouts button label, social links, home page copy section by section including the Adult pathways boxes under the pyramid, the Professional tier wording, collage, videos, what to bring, event reel, shared development pillar copy) and the `networkPage` singleton (all of /network/ except the map's club locations). Editors can't create or delete the fixed documents (programs, regions, Site settings, Network page).
  - `src/lib/sanity.ts` fetches published content at build time (with `SANITY_READ_TOKEN`, a Viewer token, set in `.env` and in Vercel; Sanity hides ids with a dot like `program.academy` from anonymous reads) and validates it with Zod; a bad document fails the build with its id and field. `src/lib/content.ts` reshapes it into the one `data` object pages and islands share (image URLs from Sanity's CDN, times and ages formatted, development copy merged into each program).
  - Publishing in the Studio triggers a Vercel rebuild through a webhook. Drafts never reach the site.
  - When a schema changes, update `studio/schemaTypes/`, the Zod schema in `src/lib/sanity.ts` and the mapping in `src/lib/content.ts` together, then `cd studio && npm run deploy`.
- **Content that stays in code:** nav, pyramid geometry, collage tile layout, compare row labels and columns, pathway, network map nodes (`NETWORK_NODES`) the fixed section headings on program pages ("Where we play", "Season overview") and the page copy on /tryouts, /events and /contact are in `src/data/site.ts` and the components. Arrows on buttons and links are added in code, so Studio fields hold the words only. Optional "Placeholder note" fields show the dashed placeholder tag until an editor clears them; rec play formats in `src/data/rec-formats.ts`; map hubs in `src/data/locations.ts`. Program and region ids are structural and live in code too.
- **Routes:** `/` home, `/<program>/` program overview, `/<program>/<region>/` region tab (all 12 exist; "soon" and "not offered" regions get their own state, never a 404), `/adult/upsl/` and `/adult/recreation/` (adult leagues, `AdultPage.jsx`; linked from the boxes under the home pyramid), `/tryouts/` (`?region=&level=`), `/events/`, `/network/`, `/contact/` (`?region=&program=`). Old `/programs/<key>/` URLs redirect (see `astro.config.mjs`).
- **Home and program pages are one React island**, `src/components/app/UAApp.jsx`: routing, transitions and region memory. It renders `Home.jsx` (collage, pyramid, tryouts near you, tournaments, network teaser, docuseries) and `ProgramPage.jsx` (hero, region tabs, overview sections), which uses `DevModel.jsx`, `CompareTable.jsx` and `RegionTab.jsx`. Opening a program pushes its URL; back/forward and Escape work. The pyramid's Professional tier zooms into `/network/`.
- **Other pages** are Astro pages with small islands: `TryoutsApp.jsx`, `EventsApp.jsx`, `ContactApp.jsx`, `NetworkMap.jsx` (d3, `src/data/world-geo.json`). `SiteHeader.jsx` and `SiteFooter.jsx` are shared by every page.
- **Region memory:** the `ua_region` cookie (1 year) plus `?region=`. Picking a region anywhere sets it; Club and Rec open on it, and so do `/tryouts/` and the header's Tryouts button. Helpers are in `src/lib/schedule.ts` (also date formatting, event status and "next tryout").
- **Dates:** tryouts in the past drop off and event status updates on the visitor's own date after load, so a stale build never shows old dates as open.
- **Locations map** (`src/components/UtahMap.jsx`, in each program's "08 · Regions" section): hubs, cities and service counties in `src/data/locations.ts`; geometry in `src/data/utah-geo.json`. Regenerate both geometry files with `npm run geo:build`. Both maps are lazy-loaded.
- **Images:** content photos are uploaded in the Studio and served from Sanity's CDN at fixed widths (`W` in `src/lib/content.ts`). `content.ts` turns each one into `{ src, pos?, alt? }`: `src` keeps the editor's crop, `pos` is a CSS position from the editor's hotspot (re-expressed relative to the crop) and `alt` is the editor's description. Components use `pos` as `object-position` (`background-position` for the home collage) and `alt` as the alt text, falling back to their own position and alt when the editor hasn't set one, so new image spots should do the same. Staff headshots render through `Headshot` in `ui.jsx`, a dashed placeholder until one is uploaded. The page heroes on /tryouts, /events and /network still use local files in `src/assets/images/` through `src/lib/assets.ts` (key, or `<key>@lg` for the large size).
- **Styles:** design tokens are in `src/styles/global.css`, along with the named hover classes (`.hv-*`), the form field class (`.ua-input`) and the phone-width rules. Components style themselves inline, matching the prototype markup. Shared pieces (kickers, buttons, form fields) are in `src/components/ui.jsx`. Use the CSS variables; don't hardcode new colors. Icons are Phosphor (`@phosphor-icons/react`).
- **Transition modes:** `expand` is the default. `zoom` and `curtain` also exist; pass `transition="zoom"` to `UAApp`, or `showModes` to show the picker dock while testing.
- `docs/` is internal and never published. `docs/rec-program-plan.md` holds rec program decisions.
- **Design updates:** follow `docs/DESIGN-SYNC.md`. Content changes from a handoff are made in the Studio, not in code. Run `npm run design:extract -- <handoff.zip, handoff folder or export.html>`, diff `docs/design-reference`, and port only what changed using the map in that doc.

## Forms and payments

- Pages are static; only `src/pages/api/*` runs on the server (Vercel adapter, `prerender = false`). Server-only helpers and the env vars they read are in `src/lib/server/index.ts`; never import it from a page or island. API URLs end in a slash (`trailingSlash: 'always'`).
- Every form uses `useSubmit` and `FormGuard` from `ui.jsx` (honeypot field plus Cloudflare Turnstile when its keys are set). `/api/submit/` saves a `submission` (contact, trial, invite, interest, register) and emails the leaders the page shows (`recipients()`: the program's region leaders, else the region's, else the main email).
- Futures registers and pays on the site: `/futures/register/?session=<id>` (`FuturesRegister.jsx`) posts to `/api/futures/checkout/`, which checks the session is open and has spots, saves a pending `futuresRegistration` and returns a Stripe Checkout link priced from Sanity. `/api/stripe/webhook/` marks it paid (emails family and leaders, sets the session Full when `capacity` is reached), expired, failed or refunded. Recreation still uses Ollie.
- `submission` and `futuresRegistration` ids contain a dot (hidden from anonymous reads), use `liveEdit` (no drafts) and can't be created in the Studio; registrations can't be deleted. Emails are skipped quietly without `RESEND_API_KEY`; the Studio is the record.

## Deploying

- Push to `main` deploys to production automatically on Vercel.
- Any other branch gets a preview URL. Use a branch for anything that needs review before going live.
- Always run `npm run build` before pushing; fix errors first.

## Writing rules

- No em dashes in any copy. Use periods, commas or colons instead.
- Keep copy short and parent-friendly. Ages are written U5, U9 to U12, etc.

## Open work

- Futures payments: needs Stripe keys and the webhook (`/api/stripe/webhook/`) set up in Stripe and Vercel, plus Resend for emails and Turnstile keys (see `.env.example`). Test end to end in Stripe test mode before switching to live keys. The Sanity publish webhook that rebuilds the site should ignore `submission` and `futuresRegistration`.
- Placeholders to replace before launch: Ollie URLs (`ollie.example`), tryout dates, times and venues, Rec/Futures session dates, event details, colors and URLs (`example.com`), event logos, staff names, emails and headshots, network copy, RC Vichy crest and photos.
- Photos: program heroes for Club, Rec and Futures are still Unsplash-derived; section photos use club photography (`collage-*`). The ECNL badge source is low-res; get a vector.
- Rec page: formats for U5 to U9 are defined; U10+ still to be decided.
- Map hubs use nearest-hub zones. Replace with the club's official city-to-hub assignment when available, and pass the matched hub into the join forms.
- Header links Staff and News from the old design were dropped; add them back to `NAV` in `src/data/site.ts` when those pages exist.
